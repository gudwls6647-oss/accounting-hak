## 발견 한 줄 요약 (v0.3 확장)

> **재무회계도 원가관리처럼 4단 계층 + 협업 단 구조다.**
> **회계학 전체가 거래 1건이 외부 공시/세법 신고서까지 가는 한 줄의 데이터 변환 파이프라인이다.**
> **각 사용자가 자기 신뢰 기준에 맞는 시점을 가진다 — 시점 = 사용자별 신뢰의 함수.**
> **모든 회계 영역의 시점 = 4개 증거(인도/소비/계약/현금)의 사용자별 가중치 차이.**

## §1. 출발점

원가관리 세션에서 4단 계층 + 협업 단(1.5/2.5/3.5단) 발견 후, 형진의 한 마디:

> "재무회계 안에도 원가관리처럼 현장 기획 재무 경영진이 있겠구나"

이 한 마디로 회계학 전체로 일반화. 그리고 5/11 세션에서 시점 차원까지 확장.

## §2. 재무회계 4단 계층 (가설)

원가관리 4단을 재무회계에 매핑:

```
[1단] 현장 = 거래 발생 + 분개 (경리/회계담당자)
  - 일반전표/매입매출전표 입력
  - "현금 1억 받음, 매출 1억 잡음"
  - 거래 그대로 기록

[1.5단] 변환 = 분류 (현장↔기획 협업)
  - 매출원가? 판관비? 영업외비용?
  - 자산? 비용? 시점은?
  - "이 거래를 어디로 보낼까"
  - = 분류 = 데이터 변환

[2단] 기획 = 손익계산서 (영업이익/당기순이익)
  - 사업기획팀이 시뮬레이션
  - 변동/고정 분리, 부문별 분석

[2.5단] 변환 = 결산 (기획↔재무 협업)
  - 감가상각, 충당금, 외화환산, 경과계정
  - "기말 시점에 장부가 현실 반영하나"
  - = 정산 = 데이터 변환

[3단] 재무 = 재무상태표 + 자본변동표 (CFO)
  - 잔액과 변동 정리
  - 외부 보고용으로 마무리

[3.5단] 변환 = 현금흐름표 작성 (재무↔경영진 협업)
  - 발생주의 → 현금주의 변환
  - "진짜 현금 어디서 들어오고 나가나"
  - = 현금 관점 데이터 변환

[4단] 경영진 = 외부 공시 + 의사결정
  - 재무제표 4종 외부 공시
  - 배당 결정, 자금 조달 결정
```

⚠️ **검증 미완성.** 원가관리 세션 끝부분 직관 발견 단계.

---

## §3. 재무제표 4종 = 데이터 변환 결과물

```
재무상태표 + 손익계산서 = 스탠다드 (raw)
  ↓
현금흐름표 = "발생주의" → "현금주의" 데이터 변환
자본변동표 = "잔액(stock)" → "흐름(flow)" 데이터 변환
```

= **재무제표 4종 = 같은 거래를 4가지 관점으로 변환한 결과물.**

---

## §4. 회계학 전체 = 한 줄의 데이터 변환 파이프라인

재무회계 4단 + 세법까지 합치면 **5단 계층**:

```
[1단]   거래 발생 → 현장 분개
[1.5단] 분류 변환
[2단]   손익계산서
[2.5단] 결산 변환
[3단]   재무상태표
[3.5단] 현금흐름표 변환
[4단]   외부 공시 (재무회계 끝)
   ↓
[4.5단] 세무조정 (회계 → 세법 변환)
   ↓
[5단]   세법 신고서 (국가 사용자)
```

= **회계학 전체가 거래 1건이 외부 공시/세법 신고서까지 가는 한 줄의 데이터 변환 파이프라인.**

---

## §5. 영역 일반화

```
원가관리: 회사 내부 4단 (공장 안에서 단이 보임)
재무회계: 회사 내부 4단 (한 회사 안의 분업이라 안 보였을 뿐)
세법:     회사(투자자 데이터) ↔ 국가(세법 데이터) 변환 (영역 간)

= 모든 회계학 영역이 4단 변환 구조
```

= 메타 anchor v1의 "사용자 관점"과 "데이터 변환"이 **같은 개념의 두 면.**

## §6. 시점 차원 — 사용자별 신뢰 기준 (v0.2 신규)

### §6.1. 회계 = 시점 차이 보정 시스템

5/11 세션에서 노무비 T-계정 분석 중 발견:

```
회계 = 현금 시점과 사용/실현 시점의 차이 보정 시스템

가장 작은 단위 — 노무비 T-계정:
  차변 (현금주의 영역): 미지급 + 당기지급 + 선급
  대변 (발생주의 영역): 사용액
  
  = T-계정 자체가 "현금주의 → 발생주의 변환기"
  = 1.5단 변환의 가장 기초 사례
```

**회계 전체로 일반화:**

```
재무회계 전체가 시점 보정의 누적:
  - 매출채권 = 매출(발생) vs 현금 수령(현금) 차이
  - 매입채무 = 매입(발생) vs 현금 지급(현금) 차이
  - 선수금/선급금 = 시점 차이
  - 감가상각 = 자산 → 비용 시간 변환
  - 충당금 = 미래 비용 미리 인식
  - 외화환산 = 평가 시점
  - 경과계정 = 기말 시점 보정
  
= 회계 = 현금 시점과 사용/실현 시점의 차이 보정 시스템
```

= **노무비 T-계정이 회계 전체 원리의 축소판.**

### §6.2. 4개 사용자 × 4개 시점

각 사용자별 신뢰 기준에 따라 시점이 다름:

```
재무회계 (사용자 = 투자자):
  발생주의 + 보수주의 + 실현주의
  - 비용 = 추정의 확장 (가능성 있으면 미리)
  - 수익 = 실현주의 (확실해야 잡음)
  → 비대칭: 비용 추정 OK, 수익 추정 NO
  = "투자자에게 안 좋은 시나리오 먼저 보여주기"

세법 손익 (사용자 = 국가):
  권리의무 확정주의 = 발생주의의 시기 조정
  - 추정 배제 (객관적 기준)
  - 보수적/객관적 시점
  → 발생주의 시점을 늦추거나 한도를 둠

부가세 (사용자 = 국가):
  증거주의 = 거래 인증 시점
  - 외부 검증 가능한 증거가 생긴 시점
  - 회계 인식과 무관
  → "거래가 일어났다는 증거가 외부에 확인 가능한 시점"

원가관리 (사용자 = 경영자):
  이중 시점 (외부 보고용 + 내부 자유)
  - 외부: 재무회계 기준 따름
  - 내부: 의사결정 시점 자유
  - 1.5단 변환 단에서 두 시점 변환
```

### §6.3. 시점 = 사용자별 신뢰의 함수

```
모든 시점 = "그 사용자가 신뢰할 수 있는 시점"

투자자 신뢰: 보수적 추정 + 실현 후 수익
국가 신뢰 (세법 손익): 법적 확정 (추정 배제)
국가 신뢰 (부가세): 외부 증거 (검증 가능)
경영자 신뢰: 의사결정에 유용한 시점

= 사용자별 신뢰 기준 = 시점 기준
```

### §6.4. 부가세 공급시기 = 증거 시점

**형진 도달한 anchor (5/11):**

```
공급시기 = 거래의 외부 확인 가능한 증거가 생긴 시점

증거 종류:
  현금적: 선수금 (가장 강력 — 거짓말 불가)
  물리적 + 법적: 인도, 계약 이행
    - 인도 = 손을 떠난 증거 (영수증/출고증)
    - 계약 = 청구권 발생 증거
  거래 종결: 수탁자 판매 (위탁만 한 건 거래 X)
  
케이스별 적용:
  재화 인도일 = 물리적 증거
  수출 선적일 = 선적서류 종합세트 + 세관 확인
  위탁판매 수탁자 판매일 = 진짜 거래 종결
  장기할부 각 시점 = 매 회차마다 청구권 새로 발생
  선세금계산서 = 현금이 가장 강력한 증거
  중간지급조건부 = 계약서가 증거
```

**6개월 기준의 정체:**

```
1 과세기간(6개월) 이내 = 한 번에 신고 가능
6개월 초과 = 두 과세기간 이상 → 나눠 신고 필요
= 국가 행정 효율 기준
```

### §6.5. 소득세 종류별 시점 = 증거 종류 차이

```
사업소득/법인세: 권리의무 확정 (회계 시스템 활용)
근로소득: 근로제공일 (근로 자체가 증거)
이자소득: 약정일 (은행 약정 = 강력한 증거)
배당소득: 결의일 (회사 결의가 증거)
연금소득: 수령일 (정기 수령이 증거)
기타소득: 수령일 (수령이 유일한 증거)
부가세: 거래 증거 시점

= 모든 세법 시점 = "증거 시점"의 변주
= 어떤 증거를 쓰냐만 다름
```

= **세법 전체가 증거주의 기반.** 다만 사업소득만 회계 시스템 있어서 권리의무 확정주의 적용 가능, 나머지는 증거주의.

### §6.6. 한 거래 = 4개 시점 동시 작동

```
거래 1건 발생:
  → 거래 증거 발생 (부가세 공급시기)
  → 발생주의 인식 (재무회계)
  → 권리의무 확정 (세법 손익)
  → 의사결정 자료 (원가관리)

= 같은 거래, 4개 시점, 4개 사용자
= 4개 다 동시 작동
```

= **회계학 = 한 거래를 4개 시점으로 변환하는 시스템.**

### §6.7. 4개 증거 시점 원리 (v0.3 핵심 발견)

**형진 도달 (5/13 부가세 작업 중):**

```
부가세 공급시기 13개 케이스 → 4개 원리로 압축

[1] 인도일 = 물리적 이동 증거 (재화)
  - 재화 인도일
  - 수출 선적일
  - 외국 인도일
  - 내국신용장 공급일
  - 간주공급 인도일

[2] 소비일 = 사용/완료 증거 (용역)
  - 용역 역무 완료일
  - 이용가능일 (임대 등)
  - 간주공급 사용·소비일
  - 폐업잔존 폐업일

[3] 계약일 = 약정/회수기일 증거 (장기/분할)
  - 장기할부 회수기일
  - 중간지급조건부 대가 수령일
  - 완성도기준지급
  - 공급확정일 (선세금계산서 예외)

[4] 현금일 = 대가 수수 증거 (선납/후납)
  - 선세금계산서 (현금 받음)
  - 일부 일반 현금 거래

= 13 케이스 = 4개 증거의 변주
```

**용어 통일 — 영역별 같은 시점 다른 이름:**

```
부가세:       소비일
재무회계:     실현/완료일
법인세:       사용수익일
근로소득세:   근로제공일
용역 일반:    역무완료일

= 같은 시점, 영역별 다른 이름
= 형진 발화: "발생주의는 너무 큰 포괄, 표현만 다르게 쓰고 있던 것"
```

**소득세 4 분류 매핑 (§6.5 강화):**

```
사업소득: 권리의무 확정 = 인도/소비/계약 (회계 기반)
근로소득: 근로제공일 = 소비일 (용역 완료)
이자소득: 약정일 = 계약일
배당소득: 결의일 = 계약일 (회사 의사결정)
연금소득: 수령일 = 현금일
기타소득: 수령일 = 현금일

= 6 종류 = 4개 증거의 변주
```

**영역별 4개 증거 가중치 — 핵심 anchor:**

```
영역별 채택 증거 가중치:

재무회계 (투자자, 실현주의):
  ① 인도 ✓
  ② 소비 ✓
  ③ 계약 ✓ (진행기준)
  ④ 현금 △ (보수적으로만 — 선수금 처리)

법인세 (국가, 권리의무 확정):
  ① 인도 ✓
  ② 소비 ✓
  ③ 계약 ✓ (진행률 OK, 1년 정산으로 추정 흡수)
  ④ 현금 △ (보조)

부가세 (국가, 증거주의):
  ① 인도 ✓
  ② 소비 ✓
  ③ 계약 ✓ (장기할부/중간지급/완성도)
  ④ 현금 ✓ (선세금계산서)
  → 4개 다 채택, 진행률은 X (회사 추정 = 외부 검증 X)

근로소득세 (국가):
  ② 소비만 (근로제공일)

이자/배당소득 (국가):
  ③ 계약만 (약정일/결의일)

연금/기타소득 (국가):
  ④ 현금만 (수령일)

원가관리 (경영자):
  내부 자유 (외부 증거 강제 X)
```

**부가세는 왜 진행률 X?**

```
진행률 = 회사 내부 추정 (총공사예정원가 / 누적공사원가)
  → 외부 검증 어려움
  → 회사 조정 여지 큼
  → 추적 강도 약함

부가세 원칙:
  외부 증거 우선 → 진행률 채택 부적합
  → 대신 "대가 수령일" (현금) 또는 "계약상 약정일" 사용

법인세 진행률 채택 이유:
  1년 정산 단위 → 추정 오차 흡수 가능
  세무조사 사후 검증 가능

= 결산 주기 + 추적 가능성 = 진행률 채택 여부 결정
```

**시점 규정 빈도 = 결산 주기 역함수 (메타 anchor):**

```
부가세 (6개월 단위):
  → 시점 분할 규정 많음 (어느 신고기간 들어가나 중요)
  → 장기할부/중간지급조건부/완성도기준지급 등

법인세 (1년 단위):
  → 시점 분할 규정 적음 (사업연도 안에만 들어가면 OK)
  → 1년 단위 정산으로 흡수

소득세 사업 (1년):
  → 법인세와 유사
  단, 원천징수는 월 단위 → 별도 시점 규정

재무회계 (분기/반기/연간 공시):
  → 실현 시점 위주
  → 분할은 매출채권 회수로 처리 (별도 규정 X)

= 결산 주기 짧을수록 시점 규정 많음
= 결산 주기 김 → 시점 규정 적음
= 같은 거래, 사용자별 결산 주기에 따라 다른 시점 규정
```

**선세금계산서 케이스 — 시점 차이 한계 사례:**

```
부가세: 3/10 세금계산서 발급 = 외부 증거 발생
재무회계: 3/20 인도 = 실현 시점

3/10 시점 분개 (적법 케이스 = 대가 받음):
  공급자: 차변 현금 / 대변 선수금 + 부가세예수금
  매입자: 차변 선급금 + 부가세대급금 / 대변 현금
  
  → 본 거래 = 선수금/선급금 (임시 계정)
  → 부가세 = 정상 계정 (즉시 인식)

3/20 인도 시점:
  공급자: 차변 선수금 / 대변 매출
  매입자: 차변 재고자산 / 대변 선급금

30일 케이스 (대가 X, 적법 분리명시):
  3/10: 미수금 / 선수금 + 부가세예수금
  → 선수금 자체가 어색 (대가 안 받음)
  → 실무 관행 분개, 본질적으로 시점 차이 한계 영역

= 부가세 시점 << 재무회계 시점 = 보정 계정으로 다리 놓기
= 회계 = 시점 보정 시스템 (v0.2 §6.1) 직접 실증
```
