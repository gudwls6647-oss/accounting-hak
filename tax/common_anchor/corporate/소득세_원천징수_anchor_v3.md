## Layer 2 — 1원리 (압축된 핵심)

> **과세관청은 행정 낭비 최소화로만 움직인다.**
>
> 표면 = 세금 / 본질 = 정보
>
> 모든 공제·면세·환급·가산세·신고의무 = "행정 효율 + 정책 의도"의 결과물

이 명제는 형진의 직관(고용주 감시 / 사업자 감시)에서 출발했고, 검색을 통해 **한국조세재정연구원·기획재정부·한국세무사회의 공식 입장과 일치**함을 확인. `[Verified Fact]`

**시험 풀이 메타 전략:**

복잡한 케이스 만나면, 두 질문 던지면 답 도출:
1. **"행정 비용이 어느 쪽이 적은가?"** (효율)
2. **"국가가 유도하려는 행동/세수가 무엇인가?"** (정책)

= 외울 게 거의 없어짐. 추론으로 도달.

## Layer 1 — 9개 작동 원리 (1원리에서 도출)

### A. 정보 회수의 3개 층 (구조)

#### 원리 1. 공급자 정보 회수 — 원천징수
- **공간 압축**: 5천만 개인 → 100만 지급의무자 (행정 효율)
- **시간 배치**: 정보 보유자가 먼저 신고 (2월 연말정산 → 3월 법인세 → 5월 종합소득세)
- **결과**: 모든 소득은 발생 즉시 국가가 알게 됨
- **시스템 한계점**: 양도소득(부동산·주식)만 원천징수 없음. 단 실거래가 신고·증권사 통보로 사실상 추적

#### 원리 2. 수요자 정보 회수 — 신용카드/현금영수증/연말정산 영수증
- **표면**: 근로자 절세 혜택
- **본질**: 자영업 매출 양성화
- **검증**: KDI/한국조세재정연구원 — *"신용카드 사용 활성화를 통한 사업자의 과표양성화를 위해 1999년 도입"*. 정부 공식 입장. `[Verified Fact]`
- **단계적 도입**: 1999 신용카드 → 2005 현금영수증 → 2010s 홈택스 자동화 → 2020s API 연동

#### 원리 3. 사업자 간 거래 정보 회수 — 부가세
- **세금계산서 / 계산서 / 카드매출전표 / 현금영수증** 합계표
- **공급자 신고 + 수요자 신고가 자동 cross-check**
- 한쪽이 거짓말하면 상대방 신고와 즉시 불일치 → 적발

→ **3층 결합 = 모든 거래가 3중 cross-check.** 국세청은 직접 조사 거의 안 해도 시스템이 자동으로 거짓말 적발.

### B. 거래 원리 3개 (인센티브 설계)

#### 원리 4. 모든 공제·비과세 = "정보 vs 세금" 거래
- 비과세 = 세금 안 떼지만 정보는 받음 (지급명세서 등)
- 공제 = 세금 깎아줌 + 영수증·증빙 회수
- 가산세 = 정보 안 주면 페널티
- 신고 의무 = 세금 안 내도 정보는 줘야 함

#### 원리 5. 공제율 = 정보 가치의 가격표

| 공제율 | 의미 | 예시 |
|---|---|---|
| 12% | 추적 완료된 영역, 가벼운 인센티브 | 보험료 |
| 15% | 기본 추적 가치 | 신용카드, 일반 의료비, 일반 교육비, 일반기부금 |
| 20% | 정책 가산 | 미숙아 의료비 |
| 30% | 더 정밀한 데이터 또는 정책 가산 | 직불·현금영수증, 도서·공연, 난임시술비 |
| 40% | 사각지대 + 정책 가산 (절실한 정보) | 전통시장, 대중교통 |
| 100% | 정치 추적 (가장 절실) | 정치자금기부금 (10만원 한도) |

**원리**: 공제율 = "이 정보가 얼마나 중요한가"의 가격. 국가가 가장 못 잡고 있는 영역일수록 공제율 높음.

#### 원리 6. 형식 기준 (Bright Line Rule)
- 검증 비용 0이 되는 형식 기준만 채택
- 실질 기준이면 검증 비용 ∞ → 행정 마비
- 약간의 부당함 vs 검증 비용 폭발 사이에서 형식 선택

| 영역 | 형식 기준 | 실질 기준이면? |
|---|---|---|
| 자가운전보조금 | 본인/배우자 명의 | "실제 운전자" 입증 — 무한 분쟁 |
| 식대 비과세 | 월 20만원 | "실제 식비"? — 영수증 다 봐야 |
| 부양가족 | 주민등록 동거 + 소득 100만원 이하 | "실제 부양"? — 사례마다 다툼 |
| 거주자 판정 | 183일 거소 | "생활 중심지" — 분쟁 |

**예외 — 부부 = 1세대**: 국세청이 이미 "부부는 한 단위"로 묶어서 추적. 검증 비용 추가 없음 → 배우자 공동명의 허용.

#### 원리 7. 이중 인센티브 차단
- 같은 비과세 인센티브를 두 갈래로 받는 것은 시스템적으로 차단
- 자가운전보조금 + 시내여비 동시 = 자가운전보조금 과세 전환
- 사내급식 + 식대 동시 = 식대 과세 전환
- 신용카드 결제 + 보험료/교육비/기부금 공제 = 신용카드 공제 배제

### C. 시스템 한계 2개

#### 원리 8. 정보 회수 ≠ 정보 처리
- 국세청 직원 약 2만 명 vs 사업자 1천만 명+, 연말정산 대상 2천만 명+
- 모든 신고서 사람이 검토 불가능 → 통계적 표본 검증
- **사실상 자기신고제 + 표본 검증제**
- 정보는 100% 회수, 분석은 ~5%만

#### 원리 9. 분쟁의 이동 — "정보 영역" → "분류·해석 영역"
- 옛날: "신고 안 했다" vs "신고 안 한 적 없다" (사실 다툼)
- 지금: "이게 어떤 소득이냐" / "이건 비용이 될 수 있냐" (분류·해석 다툼)
- 수입은 다 잡혔으니 → "그 중 얼마를 빼주느냐"가 새로운 전장
- 시스템 강화될수록 분쟁의 성격이 바뀜
- **CTA 시험의 본질이 분류·해석 능력인 이유**

**참고:** 세무회계 시험은 답이 정해진 계산 위주 → 원리 9는 anchor 이해용으로만, 시험 가중치 낮음. 해석 다툼은 세법학(판례) 영역.

## Layer 1.5 — 시점 차원 (v3 신규)

메타 anchor v3 (5.11)에서 발견된 핵심: **"사용자가 다르다 = 신뢰 기준이 다르다 → 시점이 다르다"**

소득세 영역에 적용:
```
국가 (소득세 사용자) = 어떤 시점에 인식할까?
  → 사용자의 신뢰 기준에 따라 시점 결정
  → 회계 시스템 강도 + 행정 효율 트레이드오프
```

### 4개 시점 정밀화 (소득세 적용)

```
[발생주의] — 권리·의무 발생 (회계 시스템 정밀)
  → 사업소득: 회계 시스템 활용 가능 → 권리확정주의로 변주

[권리확정주의] — 법률상 권리·의무 확정 (발생주의의 세법 변주)
  → 사업소득, 약정 있는 이자, 잉여금처분 배당
  → 추정 배제, 객관적 기준

[외부증거주의] — 외부 확인 가능한 증거 시점 (실용)
  → 근로소득(근로제공일), 광업권·저작권 양도(인도일/사용수익일)
  → 외부 검증 필수

[현금주의] — 돈 움직임 (행정 효율 우선)
  → 약정 없는 이자, 무기명 배당, 연금, 기타(원칙)
  → 회계 시스템 없거나 검증 비용 > 세수
```

= **3개 시점이 "정밀↔단순" 스펙트럼에 배치.** 사업소득만 권리확정주의(회계 활용), 나머지는 외부증거 또는 현금주의.

### 소득세 6종 시점 매핑 (이론 자료 검증 완료)

| 소득 | 시점 | 시점 분류 | 근거 |
|---|---|---|---|
| **사업소득** | 권리의무 확정 | 권리확정주의 | 회계 시스템 활용 |
| **근로소득** | 근로제공일 | 외부증거주의 | 근로 자체가 증거 |
| **이자 (약정 O)** | 약정일 | 권리확정주의 | 청구권 발생 시점 |
| **이자 (약정 X)** | 수령일 | 현금주의 | 증거 없음 → 현금 |
| **배당 (잉여금처분)** | 결의일 | 권리확정주의 | 결의 = 청구권 발생 |
| **배당 (무기명)** | 지급일 | 현금주의 | 추적 불가 → 현금 |
| **연금** | 수령일 | 현금주의 | 정기 수령 |
| **기타 (원칙)** | 수령일 | 현금주의 | 수령이 유일 증거 |
| **기타 (광업권·저작권)** | 인도일/사용수익일 | 외부증거주의 | 인도·사용 시작 증거 |

= **모든 세법 시점 = "증거 시점"의 변주.** 어떤 증거를 쓰냐만 다름.

= **사업소득만 회계 시스템 있어서 권리확정주의 적용.** 나머지는 외부증거 또는 현금.

### 형진 통찰 — 시점은 사용자별 신뢰의 함수

```
"실제수령일/지급일도 결국 현금주의"
"약정일/결의일은 권리 발생 = 청구권 = 권리확정의 변주"
"인도일/사용수익일은 외부 증거"

= 6종 시점 = "발생/외부증거/현금 3개 시점의 변주"
= 사용자(국가) 신뢰 기준의 차등 적용
```

## 9원리 × 시점 차원 매트릭스 (v3 정합성 검증)

5.11에 메타 anchor v3 통합 시 검증 완료:

| 원리 | 시점 관점 정합성 |
|---|---|
| 1. 공급자 정보 회수 (원천징수) | ✓ 시점 = 지급의무자 지급시점 = 외부증거주의 |
| 2. 수요자 정보 회수 (카드/현금영수증) | ✓ 시점 = 결제시점 = 거래 증거 시점 |
| 3. 사업자 간 거래 (부가세 cross-check) | ✓ 시점 = 공급시기 = 외부증거주의 |
| 4. 정보 vs 세금 거래 | — 시점 차원 무관 |
| 5. 공제율 = 정보 가격표 | — 시점 차원 무관 |
| 6. 형식 기준 (Bright Line) | ✓ "전일 기준 판정" = 형식 기준의 시간 차원 |
| 7. 이중 인센티브 차단 | — 시점 차원 무관 |
| 8. 정보 회수 ≠ 처리 (5% 표본) | — 시점 차원 무관 |
| 9. 분쟁의 이동 | △ 시점 분쟁(언제) = 분류 분쟁(어떤 소득)의 하위 |

**결과:**
- 9원리 중 **4개 (원리 1, 2, 3, 6)가 시점 차원과 직접 연결**
- 충돌 없음 / 9원리 재작성 불필요
- 시점 차원이 **평행 차원**으로 추가됨
- **비과세는 시점과 직교** (비과세 시점 = 과세분 시점과 동일, 시점 문제 아님)

## 가격표 두 형태 (v3 보강)

원리 5 (공제율 = 정보 가격표)의 디테일 보강. 5.11 검증에서 발견:

```
정보 가격표 = 공제율 + 한도 차등 두 형태로 발현

[공제율 형태]
  12% 보험료 / 15% 일반 / 20% 미숙아 / 30% 직불·도서 / 40% 전통시장·대중교통 / 100% 정치자금

[한도 차등 형태]
  의료비 본인·65세이상·장애인·중증환자 = 한도 무제한
  의료비 일반 = 한도 700만
  정치자금 = 10만원 한도 (소액 추적)
  
= 같은 "정보 가격표" 원리가 두 형태로 표현
```

**이론 자료 검증 결과:**
- 공제율 7개 모두 정합성 양호
- 한도 차등도 같은 가격표 원리

= **가격표 = 공제율 + 한도 두 채널.** 더 절실한 정보 = 더 높은 공제율 OR 더 큰 한도.

## 권리확정주의 vs 의무확정주의 (v3 추가)

5.11 형진 발견: **"세법은 의무확정주의 안 씀. 의무확정 = 재무회계 발생주의가 이미 작동."**

```
재무회계 (사용자 = 투자자):
  익금 = 실현주의 (확실해야 잡음, 보수적)
  손금 = 발생주의 + 추정 OK
  = 비용 추정 OK / 수익 추정 NO

세법 손익 (사용자 = 국가, 사업/법인):
  익금 = 권리확정주의 (강제 인식)
  손금 = 입증 필요 (추정 차단)
  = 익금 확장 / 손금 축소

= 사용자 입장 정확히 반대로 작동
= 보수주의의 두 얼굴
```

**소득세 영역에서의 작동:**
- 사업소득 = 권리확정주의 적용 (회계 시스템 있음)
- 다른 소득들은 회계 시스템 없음 → 외부증거주의 또는 현금주의

## 보수주의의 두 얼굴 (v3 추가)

5.11 형진 통찰: **"재무회계가 비용 보수적 = 다르게 보면 많이 잡음 → 세법은 역보수주의"**

```
재무회계 보수주의 (투자자 보수):
  비용 많이 잡기 → 회사 이익 작게 보이게 → 투자자에게 안전한 정보

세법 역보수주의 (국가 보수):
  회계가 많이 잡은 비용 다시 깎기 → 손금불산입/한도

= 둘 다 자기 사용자에게 "보수적"
= 단 보수의 방향이 정반대
```

**소득세 영역 적용:**
- 사업소득 = 재무회계 손익에서 세무조정 거쳐 종합소득에 반영
- 세무조정 = 회계의 비용 일부 → 손금불산입 (역보수주의 작동)
- 종합소득세 신고 = 세무조정 거친 사업소득금액 사용

## 세무조정 두 축 — v1 + v3 직교 결합 (v3 추가)

5.11 형진 통찰: **"유보 = 시점 차이 / 처분 (기타사외유출/상여/배당/기타) = 입장 차이"**

```
[축 1 — 시점 차원 (v3)] 유보
  유보 = 같은 사용자(회사) 내 시점만 다름
  추후 반대 조정 가능 (시점 보정)
  예: 미수이자 (권리확정 X) → 손금산입 유보 → 약정일 도래 시 익금

[축 2 — 사용자 차원 (v1)] 처분
  기타사외유출 = 회사 외부로 빠져나간 것 (접대비 한도초과)
  상여 = 임원·직원에게 귀속 (가지급금 인정이자)
  배당 = 주주에게 귀속
  기타 = 위 4개 아닌 외부 귀속
  
  → 시점 문제 아님 = 본질적 차이
  → 회사 vs 외부 입장 차이
  → 추후 반대 조정 없음
```

**소득세 영역 적용:**
- 종합소득세에 사업소득금액 반영 시 = 세무조정 거친 후 들어옴
- 인정상여 → 임원 근로소득에 가산 (= 사용자 차원 작동)
- 인정배당 → 주주 배당소득에 가산 (= 사용자 차원 작동)
- = **세무조정이 소득세 영역으로 흘러 들어오는 경로**

⚠️ 자세한 메커니즘 = 메타 anchor v3 §"세무조정 = v1 + v3 직접 결합" 참조.

## v2 추가 — 1원리에서 도출되는 보조 패턴

### 보조 1. 분리과세 = 국가의 처리 포기 영역

```
분리과세 = "이건 처리 포기, 원천징수로 마감" 선택한 영역 (처리 비용 > 세수 이익)
종합과세 = "이건 처리하겠다" 선택한 영역 (세수 큼 + 처리 가치 있음)
```

| 영역 | 처리 포기 이유 |
|---|---|
| 일용근로 무조건 분리 | 매일 다른 사업장 → 추적 비용 ∞ |
| 비과세 한도 (식대 20만 등) | 매월 영수증 검증 비용 > 세수 |
| 비과세 학자금 | 입증 비용 > 세수 |
| 근로소득공제 (의제) | 실제 근로 관련 비용 입증 → 비용 ∞ → 의제 공제 |
| 사적연금 1500만 분리 | 금융기관 분산 → 종합과세 행정 비용 큼 |
| 금융소득 2000만 컷 | 종합과세 대상 ~10-20만명 → 2만 직원이 처리 가능 규모로 컷 |

→ **컷 = "처리 가능한 규모로 자른 것".** 형진의 직관 그대로.

### 보조 2. 의제율 = 정책 우대의 가격표 (= 공제율과 동일 패턴)

| 의제율 | 대상 | 분리과세 한계 (300만 컷 역산) |
|---|---|---|
| 80% | 광업권/저작권/특허 양도, 일시 인적용역, 공익 지역권 | 1,500만까지 분리 |
| 60% | 강의·자문·학술 공모 | 750만까지 분리 |
| 0% (실액만) | 상금·복권·뇌물 | 300만까지 분리 |

→ **같은 300만 컷이지만 의제율로 4배 차이.** 우대 정도의 가격표.

### 보조 3. 일회성 vs 반복성 = 분리/종합 분기 기준

```
재발 가능성 X → 분리 (한 번 떼고 끝)
재발 가능성 ○ → 종합 (시스템에 들여서 추적)
```

| 일회성 → 분리 | 반복성 → 종합 |
|---|---|
| 복권 당첨금 | 강의료/원고료 (300만 초과) |
| 슬롯머신·경마 환급금 | 자문료 |
| 일용근로 | 사례금 |
| 부동산 양도 (별도 분류과세) | 광업권/저작권 양도 (큰 금액) |

→ 원리 1 (정보 회수)의 시간 차원 확장. **회수해야 할 미래 정보가 있으면 종합, 없으면 분리.**

### 보조 4. 실질과세 = 형식 우대 박탈

```
세법은 형식 따라가되, 실질이 다르면 형식 우대 박탈
```

| 케이스 | 형식 | 실질 | 처리 |
|---|---|---|---|
| 출자공동사업자 배당 | 배당소득 | 사업소득 | 14% → **25% 원천 + 종합 강제** |
| 보험설계·방판 사업소득 | 사업소득 | 근로 (한 회사 전속) | **연말정산 적용** |
| 위장도급 | 사업소득 | 근로 | 케이스별 판단 |

→ **국세기본법 §14 (실질과세 원칙)의 구체적 적용.** 도피 차단 + cross-check 결합.

### 보조 5. 고소득자 도피 차단 컷

```
적은 금액 = 분리과세 (행정 효율 + 세수 손실 작음)
큰 금액 = 종합과세 강제 (고소득자 도피 차단 + 누진세 보호)
```

| 영역 | 도피 차단 컷 |
|---|---|
| 기타소득금액 | 300만 |
| 사적연금 | 1500만 |
| 금융소득 | 2000만 (+ 비교과세 발동) |
| 공동사업자 배당 | 금액 무관 종합 강제 |

→ **모든 분리/종합 컷 = 행정 효율 + 세수 보호의 균형점.**

## 4-Type 공제 분류 (Layer 1 적용 결과)

원리 4-7을 통합하면, 모든 공제는 4개 Type으로 분류 가능. **분류 기준 = 추적 가능성 × 정책 의도**

### Type A. 순수 정보 회수 (감시성 우위)
- 신용카드/직불/현금영수증
- 의료비 일반 (특히 비급여 — 임플란트·라식)
- 교육비 (학원·사립)
- 기부금 (특히 일반기부금·종교)

### Type B. 정보 + 정책 혼합 (사각지대 핀셋)
- 전통시장 40%, 대중교통 40%
- 도서·공연·박물관 30%
- 월세 (임대 사각지대 + 주거 정책)
- 현금영수증 의무발급 업종

### Type C. 순수 정책 유도 (정보 회수 거의 없음)
- 연금계좌 (노후 3층 보장)
- 장기주택저당차입금 이자 (자가보유)
- 주택청약저축 (청약 유도)
- 난임시술비 30% / 미숙아 20% (저출산)

### Type D. 순수 혜택 (가족 부담 경감)
- 보험료 (보험사 추적 완료, 한도 작음)
- 인적공제 (기본 150만)
- 자녀세액공제
- 결혼세액공제 (출산 정책 일부 섞임)

**분류 기준:**
- 추적 가능 + 정책 없음 → Type D
- 추적 어려움 + 정책 없음 → Type A
- 추적 어려움 + 정책 있음 → Type B
- 추적 가능 + 정책 있음 → Type C

## 4-Type × 시점 분기 (v3 추가)

각 Type이 시점 차원과 어떻게 결합하는가:

### Type A (정보 회수) — 시점 = 거래 증거 시점

```
신용카드/직불/현금영수증:
  시점 = 결제일 (외부증거주의)
  → 카드사·POS 자동 기록
  → 시점 분쟁 거의 없음

의료비 일반:
  시점 = 진료비 영수증 발급일 (외부증거주의)
  → 의료기관 자동 추적

교육비 (학원·사립):
  시점 = 납입 영수증 (외부증거주의)
  → 학원 자동 추적

기부금 (일반·종교):
  시점 = 기부금 영수증 발급일 (외부증거주의)
  → 단체 추적
```

**출제 패턴:** "어떤 결제수단으로 어떤 시점에 결제됐나" — **외부증거 시점 정확히 잡기**.

### Type B (정보 + 정책) — 시점 = 동일 + 한도 조건

```
전통시장·대중교통:
  시점 = 결제일 (외부증거주의)
  + 총급여 한도 (7천만/8천만 컷)
  
도서·공연:
  시점 = 결제일
  + 총급여 7천만 한도

월세:
  시점 = 월세 지급일
  + 총급여 8천만 한도
```

**출제 패턴:** "총급여 한도 + 시점" 결합. **한도와 시점 다 챙기기**.

### Type C (정책 유도) — 시점 = 다양

```
연금계좌:
  시점 = 납입일 (현금주의)
  → 노후 정책 → 시점보다 누적금액 중요

장기주택저당차입금 이자:
  시점 = 이자 지급일 (외부증거주의)
  → 발생주의 아님 (현금 지급 기준)

주택청약저축:
  시점 = 납입일 (현금주의)

난임시술비·미숙아:
  시점 = 의료비 결제일 (외부증거주의)
```

**출제 패턴:** "정책 자격 조건 + 시점" — **자격 요건이 시점보다 핵심**.

### Type D (순수 혜택) — 시점 = 단순

```
보험료:
  시점 = 납입일 (현금주의)
  → 보험사 추적, 시점 단순

인적공제:
  시점 = 과세기간 말 (12.31) 기준
  → 가족 상태 판정 시점

자녀세액공제:
  시점 = 12.31 기준
  → 자녀 수 판정
```

**출제 패턴:** "12.31 기준 판정 vs 실제 발생" — **형식 기준 시점 적용**.

### 통합 — 출제 패턴 시점 예측

```
[Type A] → 외부증거 시점 잡기 (결제일·영수증일)
[Type B] → 외부증거 + 한도 결합
[Type C] → 정책 자격 + 시점 (시점은 부차적)
[Type D] → 12.31 형식 기준 시점
```

= **Type 분류 + 시점 차원 = 출제 패턴 자동 예측.** 1주차/3주차 진입 시 직접 활용 가능.

## 학습 적용법

### 1주차 (A 모듈, 사원등록·급여·원징신고서) 진입 시

수당공제등록 메뉴의 비과세 항목 약 30개는 다음 4개 질문으로 분류 (v3 Q4 시점 추가):

1. **형식 기준이 뭔가?** (한도 / 명의 / 자격) → 원리 6
2. **이중 수령 차단 조항은?** (어떤 다른 항목과 동시 수령 금지?) → 원리 7
3. **정보 회수 측면은?** (지급명세서 제출 면제 vs 대상?) → 원리 4
4. **시점은?** (근로제공일? 매월 지급일?) → 시점 차원 (v3 추가)

**예: 자가운전보조금**
- 본인/배우자 명의 + 월 20만원 + 업무 사용
- 시내여비와 동시 수령 금지
- 지급명세서 제출 면제 (월 20만원 이내) ← 정보 회수 부담 줄임
- 시점 = 근로제공일 기준 (매월 정기 지급) ← 외부증거주의

4개 답이 다 나오면 그 항목은 이해 완료.

### 사원등록 3개 탭 = 9원리 매핑 (1주차 직접 적용)

```
[기본사항]      = 정보 회수 거점     → 원리 1 (공급자 정보 회수) + 시점 인식 거점
[부양가족명세]  = 형식 기준 + 이중 차단 → 원리 6 + 7 + 12.31 기준 시점
[추가사항]      = Type C 정책 유도   → 4-Type 중 정책 / 조특법 영역
```

**= 사원등록 메뉴 자체가 "한국 세무 시스템 = 다층 정보 회수"의 mini 버전.**

### 부양가족 판정 시 1원리 추론

5개 관계별 처리는 외울 필요 없음 — "행정 비용 0이 되는 처리는?"

| 관계 | 동거 인정 범위 | 1원리 적용 |
|---|---|---|
| 배우자, 직계비속, 입양자 | 무조건 | 가족 당연 추정 → 검증 무의미 |
| 직계존속 | 주거 형편 사유 + 해외 제외 | 일반적 별거 → 검증 가벼움 |
| 형제·자매 | 취업·질병·사업 + 동거 필요 | 부양 드문 케이스 → 검증 강화 |
| 장애인 | 연령 무관 | 부양 필요 명백 |
| 60세 미만 (장애 X) | 기본공제 X | 일할 수 있는 나이 → 본인공제 받으면 됨 |

### 분리/종합 판단 시 1원리 추론

4가지 질문 던지면 끝 (v3 Q4 시점 추가):

1. **데이터 보유 주체는?** 국가/공단 → 종합 가능 / 분산 → 분리 우선
2. **어느 컷이 적용되는가?** 초과면 종합 강제 (도피 차단)
3. **의제율 또는 공제율이 있는가?** 있으면 정책 우대 영역
4. **시점 기준은?** (v3 추가) 권리확정/외부증거/현금 중?

### 3주차 (B 모듈, 연말정산) 진입 시

각 공제 항목을 4-Type × 시점으로 분류 → 출제 패턴 자동 예측 (v3 시점 결합):

- **Type A (정보 회수) + 외부증거 시점**: 증빙요건 까다로움 → "신용카드 vs 현금영수증 vs 직불" 미세 구분 + 결제일 정확히 잡기
- **Type B (혼합) + 한도 + 외부증거 시점**: "총급여 7천만/8천만 한도" + 결제일
- **Type C (정책) + 자격 + 다양한 시점**: "연령요건 / 가입자격" + 시점은 부차적
- **Type D (혜택) + 12.31 형식 기준 시점**: "한도 / 중복 적용 가부" + 12.31 가족 상태

= 공제 외우는 게 아니라 **Type 분류 + 시점 분기**하면 자동으로 출제 패턴 보임.
